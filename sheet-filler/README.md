# تکمیل‌کننده‌ی گوگل‌شیت

عنوان‌ها را شما در ستون اول شیت می‌گذارید؛ این برنامه بقیه‌ی ستون‌ها را از روی
صفحه‌های سایت‌های منبع پر می‌کند و شیت را آماده‌ی تحویل به **اسکریپت درج محصول**
می‌کند.

**برنامه‌ی مستقلی است** — به هیچ پروژه‌ی دیگری وابسته نیست، دیتابیس و تنظیمات و
پنل مدیریت خودش را دارد. **هزینه‌ی API: صفر.** هیچ سرویس پولی در کار نیست.

---

## در یک نگاه

```
۱. آدرس شیت را بچسبانید        کل آدرس از نوار مرورگر — شناسه‌اش خودکار درمی‌آید
۲. سایت‌های منبع را بدهید       هر خط یک آدرس (یا فایل «عنوان → آدرس» را ایمپورت کنید)
۳. «حالت خودکار» را روشن کنید   دیگر کاری ندارید
```

هر سه در تب «شروع» پنل است. سه ورودی واقعی، بقیه خودکار.

---

## اتوماتیک تا کجا؟

**حالت خودکار** یعنی برنامه هر چند دقیقه یک‌بار خودش شیت را می‌خواند و
ردیف‌های تازه را پر می‌کند. شما فقط عنوان را در شیت می‌گذارید:

```bash
python -m sheet_filler.run fill -c config.yaml --auto --every 30
```

یا در پنل: سوییچ «حالت خودکار» را روشن کنید و «اجرا» را بزنید. تا وقتی
«توقف» نزنید کار می‌کند.

چیزهایی که **دیگر پرسیده نمی‌شوند** چون خودِ برنامه می‌فهمد:

| قبلاً پرسیده می‌شد | حالا |
|---|---|
| شناسه‌ی شیت | کل آدرس را می‌چسبانید؛ شناسه خودکار درمی‌آید |
| مسیر فایل service account | اگر کنار `config.yaml` باشد خودش پیدایش می‌کند |
| سایت‌های منبع | اگر نگاشت «عنوان → آدرس» را ایمپورت کرده باشید، از دامنه‌ی همان لینک‌ها ساخته می‌شود |
| ترتیب سایت‌ها | هر دامنه‌ای که جواب داده یاد گرفته می‌شود و دفعه‌ی بعد اول از آن می‌گردد |
| سقف نشست، اندازه‌ی دسته، آستانه‌ها | خودکار — و اجرا هر جا قطع شود از همان‌جا ادامه می‌دهد |
| «این ردیف بی‌منبع را کی دوباره امتحان کنم؟» | یک هفته بعد، خودش |
| ستون‌های شیت | از خودِ شیت خوانده می‌شوند (پایین‌تر) |

## ستون‌ها را **شیت شما** تعیین می‌کند، نه کد

این برنامه به موضوع خاصی گره نخورده. شیت رمان ستون «خلاصه» و «مترجم» دارد، شیت
نمونه‌سوال «تعداد سوالات» و «کد رایانه»، شیت جزوه «نام کتاب» و «مناسب رشته».
عنوان هر ستون سه کار می‌کند:

```
عنوان ستونِ شیت ─┬─→ برچسبی که در جدول مشخصاتِ منابع دنبالش می‌گردیم
                 ├─→ نوع ستون (از روی نامش)
                 └─→ جایی که مقدار نوشته می‌شود
```

نوع ستون از نامش حدس زده می‌شود:

| نام ستون شامل | نوع | چطور پر می‌شود |
|---|---|---|
| «تعداد ...»، «سال»، «قیمت»، «مدت» | عدد | عدد همه‌ی منابع خوشه می‌شود و پررأی‌ترین برنده است |
| «کد ...»، «شناسه»، «شماره» | متن | رأی‌گیری؛ مقدارِ تماماً عددی با رقم لاتین نوشته می‌شود |
| «آیا ...»، «دارای ...»، «... همراه» | دارد/ندارد | فقط با شاهد؛ نبودِ شاهد یعنی سلول خالی، نه «ندارد» |
| «خلاصه»، «توضیحات»، «معرفی» | خلاصه | متن جامع از همه‌ی منابع (جمله‌های تکراری حذف) |
| «نویسنده»، «مترجم»، «مدرس»، «مولف» | شخص | نام با رأی‌گیری، فارسی و لاتین با هم |
| «تصویر»، «عکس»، «کاور» | تصویر | کاور مربع بی‌واترمارک |
| «دسته»، «تگ»، «رشته»، «مناسب ...» | کرکره | فقط از گزینه‌های مجاز |
| بقیه | متن | برچسب هم‌نامِ ستون در منابع، با رأی‌گیری |

**کرکره‌ها از تبِ «لیست‌ها»ی خودِ شیت خوانده می‌شوند.** هر ستون آن تب یک کرکره
است و عنوانش باید دقیقاً همان عنوان ستون در شیت محصولات باشد. هر ستونی که آنجا
فهرست داشته باشد، مقدارش **حتماً** از همان فهرست خواهد بود. (ستون کرکره‌ای بدون
فهرست، برچسب خام منابع را می‌گیرد.)

سه شیت متفاوت، بدون یک خط تغییر در کد:

```
شیت رمان        عنوان | keyword | Author | Summary | Categories | Tags | Nationality | Format | Translator | Pages | Image | Status | Product ID
شیت نمونه سوال   عنوان | کلمه کلیدی | تعداد سوالات | کد رایانه | تعداد صفحه | جزوه همراه | دسته بندی | مناسب رشته | تصویر | وضعیت | Product ID
شیت جزوه        عنوان | کلمه کلیدی | نام کتاب | نویسنده کتاب | تعداد صفحه | مناسب رشته | خلاصه | تصویر
```

اگر تشخیصی غلط بود، در `config.yaml` تصحیحش کنید:

```yaml
sheet:
  columns:
    "زمان آزمون":
      kind: number
      labels: ["مدت زمان آزمون", "زمان پاسخگویی"]
      max_value: 500
```

## نصب

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r sheet_filler/requirements.txt
cp sheet_filler/config.example.yaml config.yaml
```

روی ویندوز:

```cmd
python -m venv .venv && .venv\Scripts\activate
pip install -r sheet_filler\requirements.txt
copy sheet_filler\config.example.yaml config.yaml
```

**حداقل وابستگی‌ها `typer` و `PyYAML` است.** بقیه اختیاری‌اند:

| بسته | نبودش یعنی |
|---|---|
| `gspread` | نمی‌شود در گوگل‌شیت نوشت (فقط فایل csv/xlsx محلی) |
| `openpyxl` | فایل xlsx خوانده/نوشته نمی‌شود (csv کار می‌کند) |
| `curl_cffi` | برگشت به urllib — بعضی سایت‌ها ممکن است پاسخ ندهند |
| `rapidfuzz` | تطبیق عنوان با difflib (کندتر، نتیجه‌ی مشابه) |
| `Pillow` | تشخیص «همین کاور در سایت دیگر» فقط روی فایل کاملاً یکسان |
| `playwright` | سایت‌های JS-heavy محتوایشان را نمی‌دهند |

### آماده‌سازی گوگل‌شیت (یک‌بار)

۱. `pip install gspread`
۲. در Google Cloud یک **service account** بسازید و فایل json کلیدش را بگیرید.
۳. شیت را با ایمیل همان service account، با دسترسی **ویرایشگر**، شیر کنید.
۴. شناسه‌ی شیت همان تکه‌ی وسط آدرس است:
   `docs.google.com/spreadsheets/d/`**`SHEET_ID`**`/edit`

اگر هنوز service account ندارید، با یک فایل `csv`/`xlsx` محلی هم کار می‌کند.

## اجرا

**ساده‌ترین راه:** فایل `start-panel.bat` (ویندوز) یا `start-panel.sh`
(لینوکس/مک) را اجرا کنید. خودش وابستگی‌ها را نصب می‌کند، اگر `config.yaml` نبود
از روی نمونه می‌سازد و پنل را بالا می‌آورد.

```bash
# پنل مدیریت در مرورگر (پیش‌فرض: پورت ۸۰۵۰)
python -m sheet_filler.run panel -c config.yaml

# شیت چه ستون‌هایی دارد و هر کدام چطور پر می‌شوند؟ (بدون نوشتن)
python -m sheet_filler.run inspect -c config.yaml --sheet https://docs.google.com/spreadsheets/d/...

# یک بار پر کن
python -m sheet_filler.run fill -c config.yaml
python -m sheet_filler.run fill -c config.yaml --limit 20      # اول با ۲۰ تا امتحان کنید

# خودکار: پر کن، بخواب، دوباره شیت را بخوان — تا وقتی نبندیدش
python -m sheet_filler.run fill -c config.yaml --auto --every 30

# ایمپورت نگاشت «عنوان → آدرس منبع» و دیدن وضعیت
python -m sheet_filler.run links  -c config.yaml --file sources.csv
python -m sheet_filler.run status -c config.yaml
```

> `python -m sheet_filler.run` باید از **پوشه‌ی والدِ** `sheet_filler` اجرا شود.
> اگر داخل خود پوشه هستید، `python run.py panel -c ..\config.yaml` همان کار را می‌کند.

## پنل مدیریت

سه تب، نه بیشتر:

| تب | کار |
|---|---|
| شروع | آدرس شیت، سایت‌ها، حالت خودکار، و **بررسی شیت بدون نوشتن**. تنظیم‌های ریز زیر «پیشرفته» جمع شده‌اند. |
| اجرا و لاگ | دکمه‌ی اجرا/توقف، شمارنده‌ها، لاگ زنده، دانلود خروجی |
| ردیف‌ها | وضعیت هر ردیف با ستون‌های همان شیت و دلیل ناقص ماندن |

دکمه‌ی **«آزمایش با ۲۰ ردیف»** هم هست: قبل از اینکه ۱۵ هزار ردیف را راه
بیندازید، روی بیست‌تا ببینید نتیجه چطور است.

سرور فقط روی `127.0.0.1` گوش می‌دهد، هدر `Host` را چک می‌کند و هر درخواست API
به توکن نشست نیاز دارد — همان لینکی که ترمینال چاپ می‌کند را باز کنید.

## منابع هر عنوان از کجا می‌آیند

به همین ترتیب:

1. **ستون آدرس در خودِ شیت** — اگر ستونی دارید که لینک صفحه‌ی محصول در آن است،
   نامش را در `sheet.sources_column` بگذارید. سریع‌ترین و دقیق‌ترین حالت.
2. **نگاشت ایمپورت‌شده** — یک فایل csv/xlsx با یک ستون عنوان و یک ستون آدرس
   (خروجی هر ابزار دیگری) را با `links` وارد کنید؛ در دیتابیس می‌ماند.
3. **جستجو در خودِ سایت‌های منبع** — `/?s=` وردپرس یا هر قالبی که در config
   بدهید. از موتور جستجوی خارجی استفاده نمی‌شود.

در هر سه حالت، صفحه‌ای که عنوانش با عنوان شما نخواند (شباهت کمتر از
`fill.min_title_similarity`) کنار گذاشته می‌شود.

## تصویر: مربع و بی‌واترمارک، بدون API

مربع بودن **قطعی** بررسی می‌شود: اندازه یا در خود HTML اعلام شده، یا در نام فایل
وردپرسی (`cover-600x600.jpg`) هست، یا از هدر خود فایل خوانده می‌شود — و برای
خواندن هدر فقط ۶۴ کیلوبایت اول با `Range` گرفته می‌شود، نه کل تصویر.

واترمارک‌نداشتن قطعی نیست، پس سه شاهد کنار هم گذاشته می‌شود:

1. آدرس و متن جایگزین تصویر (`watermark`، `logo`، نام سایت در نام فایل، ...)
2. **تکرار بین دامنه‌ها** — واترمارکِ هر سایت مال خودش است، پس تصویری که عین
   همان در دو دامنه دیده شود تقریباً همیشه کاور اصلی ناشر است
3. `image.prefer_domains` / `image.block_domains` که خودتان می‌دهید

تصویری که اندازه‌اش تأیید نشود نوشته نمی‌شود: سلول خالی بهتر از لینک تصویر
مستطیلِ واترمارک‌دار است.

## ۱۵ هزار عنوان را چطور اجرا کنم

حالت خودکار را روشن کنید و رهایش کنید. با احترام به سقف «۱ درخواست در ثانیه به
هر دامنه» هر عنوان چند ثانیه طول می‌کشد، ولی:

* اجرا **از سر گرفتنی** است: هر ردیف بلافاصله ذخیره می‌شود.
* استخراج هر صفحه **کش** می‌شود؛ اجرای بعدی برای عنوان‌های قبلی درخواستی نمی‌زند.
* ردیفی که یک‌بار پر شد دوباره در صف نمی‌آید (مگر «صف را از نو بساز» را بزنید).
* ردیف **بی‌منبع** یک هفته بعد خودش دوباره امتحان می‌شود — شاید منبعی تازه
  محصول را گذاشته باشد.
* نوشتن در شیت دسته‌ای است و **فقط سلول‌های هدف** نوشته می‌شوند.
* اگر اجرا وسط نوشتن قطع شود، اجرای بعدی همان سلول‌های ننوشته را می‌نویسد.

## گزارش

کنار شیت محصولات یک تب «گزارش تکمیل» ساخته می‌شود: برای هر ردیف، تعداد منابع،
مقدار و **تعداد رأی** هر ستون، و اینکه کدام ستون پر نشد و چرا. ردیف‌های «ناقص»
و «تک‌منبعی» همان‌هایی هستند که ارزش دارد دستی نگاهشان کنید.

## معماری

```
sheet_filler/
├── run.py                  CLI: panel | inspect | fill | links | status
├── launch.py               راه‌انداز دو-کلیکی (پیام‌های فارسی)
├── start-panel.bat / .sh
├── config.example.yaml
├── core/
│   ├── settings.py         تنظیم‌های کاربر — یک جای تعریف؛ فرم پنل از رویش ساخته می‌شود
│   ├── config.py           بارگذاری config
│   ├── db.py               اسکیما و state (شیت‌ها، ردیف‌ها، کش، نگاشت‌ها)
│   ├── normalizer.py       نرمال‌سازی فارسی + ساخت کلمه‌ی کلیدی
│   ├── similarity.py       شباهت متنی (rapidfuzz / difflib)
│   ├── http.py             curl_cffi + robots + rate limit + Playwright
│   ├── extract.py          پارس HTML، لینک‌ها، JSON-LD
│   ├── details.py          استخراج همه‌ی برچسب/مقدارهای یک صفحه
│   ├── fields.py           نوع هر ستون شیت (هر موضوعی، بدون کد تازه)
│   ├── consensus.py        رأی‌گیری بین منابع
│   ├── taxonomy.py         نگاشت برچسب منابع به کرکره‌ها
│   ├── images.py           انتخاب کاور مربعِ بی‌واترمارک
│   ├── gsheet.py           خواندن/نوشتن گوگل‌شیت یا فایل محلی
│   ├── sources.py          پیدا کردن صفحه‌های هر عنوان
│   └── filler.py           موتور تکمیل
├── web/
│   ├── server.py           پنل مرورگری (http.server استاندارد)
│   ├── jobs.py             اجرای پس‌زمینه + لاگ زنده
│   └── static/             صفحه‌ی راست‌چین فارسی، بدون CDN
├── tests/                  ۶۳ تست، بدون شبکه
└── data/                   دیتابیس و خروجی‌ها
```

اصول:

1. هر تنظیم **یک** جا تعریف می‌شود (`core/settings.py` برای انتخاب‌های کاربر،
   `FillOptions` برای پیش‌فرض‌ها) و فرم پنل از رویش ساخته می‌شود.
2. هیچ داده‌ای فقط در RAM نمی‌ماند؛ هر ردیف بلافاصله نوشته می‌شود.
3. هر صفحه‌ی منبع یک‌بار دانلود و استخراج می‌شود و در `pages` می‌ماند.
4. سلول پرشده دست نمی‌خورد، و «وضعیت»/«شناسه محصول» هیچ‌وقت نوشته نمی‌شوند.
5. حدس نمی‌زنیم: نبودِ شاهد یعنی سلول خالی، نه مقدار پیش‌فرض.

## تست

```bash
python -m pytest sheet_filler/tests -q
```

هیچ تستی به شبکه یا حساب گوگل نیاز ندارد. پوشش: استخراج برچسب‌ها، رأی‌گیری
(عدد، نام، خلاصه، بله‌وخیر)، ساخت کلمه‌ی کلیدی، نگاشت کرکره‌ها، انتخاب تصویر،
شیت‌های چند موضوع مختلف، از سرگیری و کش، و API پنل.
