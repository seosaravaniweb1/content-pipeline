# ابزار استخراج و تحلیل خوراک محتوایی

ابزار پایتونی برای استخراج عناوین محصولات از سایت‌های رقیب، ادغام هوشمند
نام‌های تکراری، و تفکیک محصولات دارای ساجست از بدون ساجست. دو رابط دارد:
یک CLI و یک **پنل مدیریت در مرورگر** (`run panel`).

**هزینه‌ی API: صفر.** هیچ سرویس پولی استفاده نمی‌شود.

---

## جریان کار در یک نگاه

```
۱. نوع محصول را تیک بزنید      جزوه | رمان | کتاب | کتاب درسی | دانشگاهی | دانش‌آموزی
۲. لینک سایت‌ها را بچسبانید     تا ۳۰۰ آدرس، هر خط یکی
۳. دکمه‌ی اجرا                  کراول → ادغام تکراری‌ها → ساجست گوگل
۴. خروجی                        اکسل با ستون «ساجست: دارد / ندارد»
```

هر سه مرحله در تب «شروع» پنل مرورگری است؛ نیازی به دست زدن به فایل تنظیمات
نیست. می‌توانید چند دسته را با هم انتخاب کنید — هر عنوان به نزدیک‌ترین دسته
نسبت داده می‌شود و همان نام در ستون «دسته»ی خروجی می‌آید.

---

## خروجی

چهار شیت در یک فایل اکسل (یا یک گوگل‌شیت). از تب «شروع» پنل یا کلید
`output.sheets` انتخاب می‌کنید کدام‌ها ساخته شوند:

**شیت A — «آماده تولید محتوا»** (`has_suggest`)

| ستون | توضیح |
|---|---|
| `canonical_title` | عنوان یکپارچه |
| `lsi_keywords` | کلمات پیشنهادی گوگل، جدا شده با `\|` |
| `lsi_count` | تعداد ساجست‌ها (برای اولویت‌بندی) |
| `source_domains` | دامنه‌هایی که این محصول در آن‌ها بود |
| `source_urls` | لینک‌های اصلی |
| `category` | دسته‌ی تشخیص‌داده‌شده (رمان، جزوه، ...) |
| `merge_count` | چند عنوان خام در این رکورد ادغام شده |
| `confidence` | امتیاز اطمینان ادغام |

**شیت B — «آرشیو آینده»** (`no_suggest`) — همان ستون‌ها بدون `lsi_keywords`.

**شیت «همه محصولات»** — همه‌ی محصولات در یک جا با ستون `suggest` که مقدارش
«دارد»، «ندارد» یا «بررسی نشده» است. («بررسی نشده» یعنی هنوز فاز ۳ روی آن
اجرا نشده — در پنل با برچسب «در صف» دیده می‌شود.)

هر فهرست را جداگانه هم می‌شود دانلود کرد (اکسل یا CSV) و هم همه را در یک فایل
چندشیتی. دانلود همان لحظه از دیتابیس ساخته می‌شود، پس ادغام‌های دستیِ بعد از
فاز ۴ هم در آن هست. اگر می‌خواهید همه‌چیز را یکجا داشته باشید
ولی تفکیک ساجست را هم از دست ندهید، همین شیت را بگیرید.

**شیت C — «نیاز به بازبینی دستی»** — دو نوع ردیف با ستون `type`:
«ادغام مبهم» (ابزار مطمئن نبود ادغام کند یا نه) و «ارتباط مرزی با موضوع»
(امتیاز موضوعی بین دو آستانه).

## نصب

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r content_pipeline/requirements.txt
playwright install chromium        # فقط اگر سایت JS-heavy دارید

cp content_pipeline/config.example.yaml config.yaml
```

روی ویندوز:

```cmd
python -m venv .venv && .venv\Scripts\activate
pip install -r content_pipeline\requirements.txt
copy content_pipeline\config.example.yaml config.yaml
```

**حداقل وابستگی‌ها `typer` و `PyYAML` است.** بقیه اختیاری‌اند و پایپ‌لاین بدون
آن‌ها هم اجرا می‌شود، ولی با کیفیت یا ریسک بیشتر:

| بسته | نبود آن یعنی |
|---|---|
| `curl_cffi` | برگشت به urllib کتابخانه‌ی استاندارد — اثرانگشت TLS شناسایی می‌شود (CLI هشدار می‌دهد) |
| `rapidfuzz` | شباهت با `difflib` (کندتر، نتیجه‌ی مشابه) |
| `sentence-transformers` | انکودر جایگزین hashing tf-idf — تشخیص موضوعی ضعیف‌تر |
| `selectolax` | `title_selector` سفارشی کار نمی‌کند (h1/og:title/title کار می‌کنند) |
| `openpyxl` | خروجی به‌جای xlsx، سه فایل CSV |
| `playwright` | سایت‌های JS-heavy عنوان نمی‌دهند |

## اجرا

```bash
# ساخت دیتابیس
python -m content_pipeline.run init-db -c config.yaml

# اجرای کامل (چهار فاز)
python -m content_pipeline.run start -c config.yaml

# ادامه از فاز ۳ روی آخرین اجرا (فازهای ۱ و ۲ تکرار نمی‌شوند)
python -m content_pipeline.run start -c config.yaml --resume-from 3

# فقط چند فاز مشخص
python -m content_pipeline.run start -c config.yaml --phases 1,2

# یک فاز روی یک اجرای مشخص
python -m content_pipeline.run phase 3 -c config.yaml --run-id 20260816-101500-ab12cd

# وضعیت، فهرست اجراها و ساخت دوباره‌ی خروجی
python -m content_pipeline.run status -c config.yaml
python -m content_pipeline.run runs   -c config.yaml
python -m content_pipeline.run export -c config.yaml --no-sheets

# ابزار کمکی: دیدن خروجی فاز ۰ روی یک متن
python -m content_pipeline.run normalize "دانلود جزوه ریاضی ۱۴۰۴ PDF"

# پنل مدیریت در مرورگر
python -m content_pipeline.run panel -c config.yaml
```

> `start` بدون `--run-id` و بدون `--resume-from` همیشه یک اجرای **جدید** می‌سازد.
> با `--resume-from N` آخرین اجرای همان موضوع ادامه پیدا می‌کند.

## پنل مدیریت در مرورگر

```bash
python -m content_pipeline.run panel -c config.yaml
# پنل روی http://127.0.0.1:8000 بالا می‌آید و مرورگر خودش باز می‌شود
python -m content_pipeline.run panel -c config.yaml --port 8100 --no-browser
```

**ساده‌ترین راه — بدون تایپ هیچ دستوری:** فایل `start-panel.bat` (ویندوز) یا
`start-panel.sh` (لینوکس/مک) داخل پوشه‌ی `content_pipeline` را اجرا کنید. خودش
وابستگی‌های لازم را نصب می‌کند، اگر `config.yaml` نبود از روی نمونه می‌سازد، و
پنل را بالا می‌آورد. اگر پورت ۸۰۰۰ اشغال بود، خودکار سراغ پورت بعدی می‌رود.
پیام‌هایش هم فارسی است، چون در `launch.py` نوشته شده‌اند نه داخل فایل bat
(توضیحش پایین‌تر در بخش «فارسی روی ویندوز»).

**نکته‌ی مهم درباره‌ی جای اجرا:** شکل `python -m content_pipeline.run` باید از
**پوشه‌ی والدِ** `content_pipeline` اجرا شود، نه از داخل خودش — وگرنه پایتون
می‌گوید `No module named 'content_pipeline'`. اگر داخل خود پوشه هستید، فایل را
مستقیم صدا بزنید؛ همان کار را می‌کند:

```cmd
:: از پوشه‌ی والد
cd C:\Users\<user>\Desktop\scrpts
copy content_pipeline\config.example.yaml config.yaml
python -m content_pipeline.run panel -c config.yaml

:: یا از داخل خود پوشه
cd content_pipeline
python run.py panel -c ..\config.yaml
```

پنل با همان کدی کار می‌کند که CLI اجرا می‌کند (`core/pipeline.py`)، پس رفتار این
دو هیچ‌وقت از هم جدا نمی‌افتد. بدون وابستگی بیرونی — سرور `http.server` استاندارد
و صفحه‌ای بدون CDN.

| بخش | کار |
|---|---|
| داشبورد | شمارنده‌های اجرا (خام، مرتبط، مرزی، یکپارچه، ساجست‌دار/بی‌ساجست) و لینک دانلود خروجی |
| اجرا | انتخاب فازها، دکمه‌ی اجرا/لغو، و لاگ زنده‌ی همان چیزی که CLI چاپ می‌کند |
| محصولات | فهرست، جستجو و فیلتر؛ **ادغام دستی**، **جدا کردن** یک عنوان از محصول، تغییر نام |
| بازبینی دستی | همان چیزی که فاز ۲ علامت زده، کنار عنوان‌های مرزی شیت C |
| تنظیمات | ویرایش و ذخیره‌ی `config.yaml` (با پشتیبان `.bak` و بررسی YAML قبل از نوشتن) |
| ابزار | آزمایش نرمال‌سازی فاز ۰ روی یک متن |

**ادغام دستی و جدا کردن، راه بازگشت‌اند.** فاز ۲ در حالت شک ادغام نمی‌کند و
مورد را به بازبینی می‌فرستد؛ از پنل می‌توانید همان‌جا تصمیم بگیرید:
یک محصول را «مقصد» انتخاب کنید و محصول دیگر را در آن ادغام کنید، یا اگر ادغامی
اشتباه بوده، عنوان خام را از محصول جدا کنید تا محصول مستقل خودش را بگیرد.

نکات عملیاتی:

* در هر لحظه فقط یک اجرا در جریان است و در حین اجرا ویرایش دستی قفل می‌شود
  (دو کراول هم‌زمان یعنی دو برابر شدن نرخ درخواست به سایت هدف).
* لغو تعاونی است: فاز جاری تمام می‌شود و فازهای بعدی اجرا نمی‌شوند؛ فاز نیمه‌کاره
  قطع نمی‌شود چون همان لحظه در حال نوشتن در دیتابیس است.
* سرور فقط روی `127.0.0.1` گوش می‌دهد، هدر `Host` را چک می‌کند، و هر درخواست API
  به توکن نشست نیاز دارد. توکن در همان لینکی است که ترمینال چاپ می‌کند — پس
  همان لینک را باز کنید، نه `localhost:8000` خالی.

## انتخاب نوع محصول و سایت‌ها

### نوع محصول

شش دسته‌ی آماده در `core/presets.py` هست — جزوه، رمان، کتاب، کتاب درسی، کتاب
دانشگاهی، کتاب دانش‌آموزی — و هرکدام ۸ نمونه‌عنوان واقعی دارد که بردار مرجع
تشخیص موضوعی از رویشان ساخته می‌شود. می‌توانید دسته‌ی دلخواه خودتان را هم
اضافه کنید (مثلاً «کتاب صوتی»).

با انتخاب چند دسته، برای هرکدام یک بردار مرجع جدا ساخته می‌شود و هر عنوان به
نزدیک‌ترینشان نسبت داده می‌شود. **میانگین گرفتن از همه‌ی دسته‌ها کار نمی‌کند:**
«رمان» و «کتاب درسی» به یک نقطه‌ی وسطِ بی‌معنا تبدیل می‌شوند و هیچ‌کدام درست
تشخیص داده نمی‌شوند.

### آستانه‌ی خودکار

آستانه‌ی ثابت با انکودرهای مختلف معنای یکسانی ندارد: انکودر جایگزین به یک
عنوانِ کاملاً مرتبط ۰.۵ می‌دهد و e5 به یک عنوان بی‌ربط ۰.۷. پس به‌جای عدد ثابت،
هر دسته آستانه‌ی خودش را می‌گیرد: نمونه‌های خودِ دسته یک سرِ طیف و چند عنوان
عمداً بی‌ربط (کفش، گوشی، بیمه، ...) سر دیگر؛ مرز وسط این دو گذاشته می‌شود.

اندازه‌گیری روی انکودر پیش‌فرض: عنوان‌های مرتبط ۰.۳۹ تا ۰.۶۰، بی‌ربط‌ها ۰.۰۱ تا
۰.۰۷. با آستانه‌ی ثابت ۰.۶۵، **همه‌ی محصولات درست دور ریخته می‌شدند.** آستانه‌ی
کالیبره‌شده در لاگ فاز ۱ چاپ می‌شود. با `run.auto_threshold: false` خاموش می‌شود.

### سایت‌ها — دو شکل آدرس، دو رفتار

| آدرس | رفتار |
|---|---|
| `https://shop.ir` | کل سایت: `robots.txt` → `sitemap.xml` → در نبودشان کراول محدود |
| `https://shop.ir/?s=رمان` یا `https://shop.ir/category/roman/` | فقط لینک‌های همان فهرست و صفحه‌های بعدی‌اش |

شکل دوم برای وقتی است که سایت دسته‌بندی درست‌وحسابی ندارد: خودتان داخل سایت
سرچ می‌کنید و آدرس صفحه‌ی نتایج را می‌دهید. لینک «بعدی» (`rel="next"` یا
`class="next"`) دنبال می‌شود تا صفحه‌های بعدی هم بیایند.

هر اجرا فهرست سایت‌های خودش را در دیتابیس نگه می‌دارد (تا ۳۰۰ آدرس)، پس اجرای
بعدی با فهرست دیگر، اجرای قبلی را دست‌کاری نمی‌کند.

### فقط صفحه‌ی محصول

بدون فیلتر، «درباره ما»، «تماس با ما» و پست‌های بلاگ هم به‌عنوان محصول وارد
خروجی می‌شوند. ملاک، چیزی است که یک صفحه‌ی فروش دارد و یک برگه ندارد:

| نشانه | وزن |
|---|---|
| داده‌ی ساخت‌یافته: `"@type":"Product"`، `og:type=product`، `itemtype=schema.org/Product` | قطعی — یکی کافی است |
| کلاس‌های فروشگاهی: `single-product`، `add-to-cart`، `data-product-id` | قطعی |
| «افزودن به سبد»، «قیمت»، «۸۵٬۰۰۰ تومان»، «موجود در انبار» | ضعیف — دوتا لازم است |
| `"@type":"BlogPosting"`/`Article`، «درباره ما»، «تماس با ما» | نشانه‌ی منفی |
| مسیر `/blog/`، `/tag/`، `/about/`، `/cart/`، `/category/` | نشانه‌ی منفی |

با تیک «فقط صفحه‌هایی که واقعاً محصول‌اند» در پنل یا
`crawl.require_product_signals` خاموش می‌شود.

### سقف و لغو

«حداکثر محصول از هر منبع» در تب شروع — برای امتحان اول ۱۰ بگذارید تا با یک
اجرای کوچک ببینید نتیجه درست است. لغو هم بین هر صفحه و هر کوئری بررسی می‌شود،
نه بعد از تمام شدن فاز؛ آنچه تا آن لحظه پیدا شده در دیتابیس محفوظ است.

## فارسی روی ویندوز

کل ابزار فارسی است — پنل، پیام‌های ترمینال، گزارش‌ها و خروجی. چند جا هست که
متن فارسی روی ویندوز خراب می‌شود و هر کدام در کد جواب داده شده:

| کجا | مشکل | کاری که شده |
|---|---|---|
| فایل `.bat` | `cmd` متن غیرانگلیسی داخل bat را نمی‌خواند و خط‌ها را تکه‌تکه اجرا می‌کند (`chcp` وسط فایل هم جای خواندنش را به‌هم می‌ریزد) | فایل bat فقط ASCII و چندخطی است؛ همه‌ی پیام‌ها در `launch.py` که پایتون چاپشان می‌کند |
| خروجی ترمینال | کنسول مشکلی ندارد، ولی خروجیِ هدایت‌شده به فایل کدگذاری محلی می‌گیرد و چاپ فارسی می‌افتد | `run.py` هنگام شروع `stdout`/`stderr` را روی UTF-8 می‌گذارد |
| `config.yaml` | Notepad ویندوز فایل را با BOM ذخیره می‌کند و YAML خطا می‌دهد | خواندن با `utf-8-sig`؛ پنل هم موقع ذخیره BOM را حذف می‌کند |
| صفحات سایت‌ها | سایت‌های قدیمی فارسی هدر charset ندارند و اغلب `windows-1256` هستند؛ خواندنشان با UTF-8 عنوان را نابود می‌کند | `extract.decode_html` به ترتیب BOM، هدر HTTP، `<meta charset>` و بعد حدس (`utf-8` سخت‌گیرانه، بعد `windows-1256`) |
| خروجی CSV | اکسل فارسی را بدون BOM اشتباه نشان می‌دهد | فایل‌های CSV با `utf-8-sig` نوشته می‌شوند |

`tests/test_encoding.py` همه‌ی این‌ها را قفل کرده است.

## معماری

```
content_pipeline/
├── run.py                  نقطه ورود CLI و پنل
├── launch.py               راه‌انداز دو-کلیکی (پیام‌های فارسی)
├── start-panel.bat         ویندوز — فقط پنل را باز می‌کند
├── start-panel.sh          لینوکس/مک
├── config.example.yaml     موضوع هدف، سایت‌ها، نمونه‌عنوان‌ها، آستانه‌ها
├── core/
│   ├── db.py               اسکیما و لایه‌ی state
│   ├── normalizer.py       فاز ۰ — نرمال‌سازی فارسی
│   ├── cache.py            کش کوئری‌های ساجست
│   ├── suggest.py          کلاینت گوگل ساجست + قواعد ایمنی
│   ├── entities.py         توکن تمایزدهنده (مرحله B فاز ۲)
│   ├── similarity.py       شباهت متنی (rapidfuzz / difflib)
│   ├── embeddings.py       بردارسازی (e5 / hashing tf-idf)
│   ├── extract.py          پارس HTML، sitemap و رمزگشایی کدگذاری
│   ├── presets.py          دسته‌های آماده‌ی محصول + نمونه‌های بی‌ربط
│   ├── pipeline.py         اجرای فازها — مشترک بین CLI و پنل
│   ├── http.py             curl_cffi + robots + rate limit + Playwright
│   └── config.py           بارگذاری config
├── phases/
│   ├── p1_crawl.py
│   ├── p2_resolve.py
│   └── p3_suggest.py
├── output/
│   └── exporter.py         سه شیت (اکسل / گوگل‌شیت)
├── web/
│   ├── server.py           پنل مرورگری (http.server استاندارد)
│   ├── jobs.py             اجرای فاز در پس‌زمینه + لاگ زنده
│   └── static/             صفحه‌ی راست‌چین فارسی، بدون CDN
├── tests/                  ۲۴۵ تست، بدون شبکه
└── data/                   runs.db و خروجی‌ها (در git نیست)
```

اصولی که در کد اعمال شده‌اند:

1. چهار فاز مستقل؛ ارتباط فقط از طریق SQLite
2. هر فاز نتیجه را بلافاصله می‌نویسد — هیچ‌چیز فقط در RAM نمی‌ماند
3. `--resume-from N` کار می‌کند (فاز ۳ فقط محصولات بدون وضعیت را می‌گیرد)
4. Idempotent: `UNIQUE` + `INSERT OR IGNORE` در هر جدول
5. هر کوئری ساجست یک‌بار زده می‌شود و در `api_cache` می‌ماند

## فازها

### فاز ۰ — نرمال‌سازی فارسی (پیش‌نیاز حیاتی)

`core/normalizer.py`. هر عنوان قبل از هر پردازشی از این خط عبور می‌کند:

- `ي`/`ك` عربی → `ی`/`ک` (به‌علاوه `ة`، `أ`، `إ`، `ؤ`، `ئ`، `ۀ`)
- یکسان‌سازی نیم‌فاصله و حذف نیم‌فاصله‌های اضافه (و «ه‌ی/ه‌ای» اضافه)
- یکسان‌سازی ارقام (پیش‌فرض فارسی، ثابت و یک‌طرفه)
- حذف اعراب و کشیده
- حذف کلمات ایستای تجاری: دانلود، خرید، رایگان، pdf، فایل، کامل، جدید، نسخه،
  اورجینال و سال‌ها (۱۴۰۳، ۱۴۰۴، ...)
- حذف نشانگرهای ساختاری: «از»، «نوشته»، «اثر»، «استاد»، «دکتر»، «جلد»، ...
  این‌ها اسمِ چیزی نیستند، فقط به نام بعدی اشاره می‌کنند. اگر بمانند،
  «شب سرما نوشته الناز» و «شب سرما الناز» شباهت کمتری می‌گیرند و ادغام
  از دست می‌رود
- نرمال‌سازی فاصله‌های چندگانه و trim

`raw_title` دست‌نخورده می‌ماند؛ خروجی در `normalized_title`.
`tests/test_normalizer.py` روی **۲۰ نمونه‌ی واقعی** اجرا می‌شود — عنوان‌های سایت
خودتان را به `REAL_SAMPLES` اضافه کنید.

### فاز ۱ — کراول و تشخیص موضوعی

`robots.txt` → `sitemap.xml` (+ ایندکس‌ها) → در نبودشان کراول محدود با
`max_depth`. هر صفحه با `curl_cffi` و `impersonate="chrome"`؛ روی ۴۰۳/۴۲۹/۵۰۳ یا
صفحه‌ی پوسته‌ای، fallback به Playwright. حداکثر ۱ درخواست در ثانیه به هر دامنه و
احترام به `robots.txt`.

عنوان به ترتیب از `<h1>` → `og:title` → `<title>` (با حذف نام سایت). نام سایت
فقط وقتی حذف می‌شود که قابل اثبات باشد — از `og:site_name`، نام دامنه، یا
`site_name` در config. اگر شناسایی نشد، عنوان دست‌نخورده می‌ماند تا توکن
تمایزدهنده‌ای مثل «جلد دوم» تصادفاً حذف نشود.

`score >= 0.65` مرتبط، `0.50..0.65` به شیت C، کمتر رد.

### فاز ۲ — Entity Resolution (حساس‌ترین فاز)

| مرحله | کار |
|---|---|
| A | بلاک‌بندی بر اساس نادرترین کلمات عنوان پایه |
| B | توکن تمایزدهنده: **نویسنده/مدرس**، عدد، جلد/پارت، برند لاتین |
| C | قانون ادغام |

**نویسنده مهم‌ترین سیگنال هویت است.** عنوان به‌تنهایی کافی نیست:

```
نویسنده‌ها متفاوت                 →  خط قرمز، حتی اگر عنوان‌ها تقریباً یکی باشند
جلد/شماره/برند متفاوت             →  خط قرمز

نویسنده‌ها یکسان                  →  ادغام، اگر شباهت عنوان >= ۰.۸۸
فقط یک طرف نویسنده دارد           →  اگر تنها یک نویسنده در میدان است ادغام،
                                     وگرنه شیت C
هیچ‌کدام نویسنده ندارند            →  ادغام فقط اگر شباهت >= ۰.۹۵، وگرنه شیت C
```

چرا «نویسنده‌ی یکسان» آستانه را پایین نمی‌آورد؟ چون یک نویسنده چند رمان
می‌نویسد. اندازه‌گیری روی نمونه‌های واقعی نشان داد:

| جفت | شباهت | نتیجه |
|---|---|---|
| «شب سرد از الناز» / «شب سرما از الناز» | ۰.۹۱ | یک رمان — ادغام |
| «شب سرد از الناز» / «شب بخیر از الناز» | ۰.۸۶ | دو رمان از یک نویسنده — شیت C |
| «شب هات از سحر» / «شب گرم از الناز» | ۰.۶۱ | نویسنده متفاوت — خط قرمز |
| «شب سرد» / «شب گرم» | ۰.۸۲ | بدون نویسنده، شباهت ناکافی — شیت C |
| «شب سرد» / «شب سرد کامل» | ۱.۰۰ | یک رمان — ادغام |
| «شب سرد» / «شب سرد الناز» | ۰.۹۱ | یک رمان — ادغام از روی نویسنده |

دو باند «یک رمان» و «دو رمان از یک نویسنده» در ۰.۸۵۸ تا ۰.۸۶۳ همپوشانی دارند،
پس مرز روی ۰.۸۸ (بالای باند دوم) گذاشته شده: جفت‌های وسط این بازه به‌جای ادغام
به شیت C می‌روند. با `resolve.strong_match_threshold` قابل تنظیم است.

«نام + نام خانوادگی» یک نویسنده شمرده می‌شود: «الناز» و «الناز محمدی» هم‌پوشانی
دارند، نه دو نفر.

نام نویسنده از سه راه پیدا می‌شود: نشانگر صریح («از الناز»، «نوشته الناز»)،
گازتیر نام‌های فارسی (`core/data/fa_given_names.txt` — با
`normalizer.extra_names` قابل افزودن)، و نشانگر نقشی («استاد کریمی»). نشانگر
نقشی سخت‌گیرانه‌تر است و فقط وقتی نام می‌گیرد که آن کلمه در گازتیر باشد یا آخر
عنوان بیاید — وگرنه در «رمان استاد مغرور الناز» کلمه‌ی «مغرور» نویسنده شمرده
می‌شد و «استاد مغرور الناز» با «استاد مغرور سحر» اشتباهی ادغام می‌شدند.

**عنوانی که نویسنده ندارد** فقط وقتی به یک محصول می‌چسبد که برای آن عنوان پایه
**تنها یک** نویسنده وجود داشته باشد:

* «شب سرد» + «شب سرد الناز» → یک رمان
* «تاوان خیانت از ناشناس» + «تاوان خیانت آوا» + «تاوان خیانت مهسا» → معلوم نیست
  مال کدام است، پس ادغام نمی‌شود و به شیت C می‌رود

**قانون طلایی در کد اعمال شده، نه فقط در توضیحات:** خوشه‌بندی حریصانه است ولی
هر اتحاد قبل از اجرا چک می‌کند که هیچ جفت «خط قرمز» داخل خوشه نیفتد — یعنی حتی
مسیر انتقالی (آوا ~ بدون‌نام ~ مهسا) هم نمی‌تواند دو محصول متفاوت را یکی کند.

سناریوی مرجع داکیومنت در `tests/test_resolver.py` قفل شده است:

| عنوان | توکن تمایزدهنده | نتیجه |
|---|---|---|
| رمان تاوان خیانت آوا | `{آوا}` | با نسخه‌ی «دانلود ... pdf» ادغام می‌شود |
| رمان تاوان خیانت مهسا | `{مهسا}` | خط قرمز نویسنده — جدا می‌ماند |
| رمان تاوان خیانت از ناشناس | `{}` | شیت C — ادغام نمی‌شود |
| رمان تاوان خیانت ۴ برادر | `{۴ برادر}` | خط قرمز — جدا می‌ماند |

تصمیم‌های هر اجرا در `data/review/<run_id>_merge_decisions.json` لاگ می‌شوند —
برای هر جفت، امتیاز شباهت و دلیل تصمیم.

### فاز ۳ — گوگل ساجست

**کوئری، عنوان محصول نیست.** عنوان فروشگاهی مثل «دانلود رمان دانلود رمان بهار
رضوانی از حدیثه نسخه کامل و اصلی pdf» چیزی نیست که کسی در گوگل تایپ کند و
گوگل هم برایش پیشنهادی ندارد — نتیجه‌اش این است که **همه‌ی محصولات «بدون
ساجست» علامت می‌خورند**. پس کوئری ساخته می‌شود:

```
دانلود رمان دانلود رمان بهار رضوانی از حدیثه نسخه کامل و اصلی pdf
      ↓  حذف پیشوند تکراری، کلمات فروشگاهی، سال‌ها و کلمات تکراری
رمان بهار رضوانی حدیثه
```

نیم‌فاصله در کوئری حفظ می‌شود (برخلاف فرم تطبیق): «پیش‌دانشگاهی» به
«پیشدانشگاهی» تبدیل شود دیگر کلمه‌ی قابل جستجویی نیست. طول کوئری با
`suggest.max_query_words` محدود می‌شود. کوئری هر محصول در تب «محصولات» پنل
دیده می‌شود، پس قبل از اجرا می‌توانید بررسی‌اش کنید.

**یک شکل کوئری کافی نیست.** روی نمونه‌های واقعی دیدیم که «رمان ارباب تعصبی من
ناشناس» هیچ پیشنهادی ندارد ولی «رمان ارباب تعصبی من» دارد، و «پی دی اف رمان
ارباب تعصبی من» هم دارد. پس چند شکل امتحان می‌شود، از دقیق‌ترین به عمومی‌ترین:

```
۱. رمان ارباب تعصبی من ناشناس     ← عنوان تمیزشده
۲. رمان ارباب تعصبی من            ← یک کلمه کوتاه‌تر
۳. دانلود رمان ارباب تعصبی من     ← با پیشوند رایج
۴. رمان ارباب تعصبی               ← دو کلمه کوتاه‌تر
```

به‌محض رسیدن به `suggest.enough_keywords` کلمه، بقیه‌ی شکل‌ها امتحان نمی‌شوند
تا کوئری هدر نرود. تعداد شکل‌ها با `suggest.max_variants_per_product` و
پیشوندها با `suggest.query_prefixes` تنظیم می‌شوند.

**پیشنهادهای بی‌ربط حذف می‌شوند.** گوگل برای «رمان ارباب تعصبی» هم «رمان ارباب
تعصبی من» می‌دهد (مرتبط) و هم «رمان غرور و تعصب» (بی‌ربط). ملاک نگه‌داشتن این
است که کلمات خودِ عبارت جستجو در پیشنهاد آمده باشند
(`suggest.min_keyword_coverage`، پیش‌فرض ۱.۰ یعنی همه‌ی کلمات). کوئری‌ای که هر
کلمه را پیدا کرده در `lsi_keywords.source_query` ذخیره و در پنل نشان داده
می‌شود.

**«خالی» با «خطا» یکی نیست.** پاسخ ۲۰۰ با فهرست خالی یعنی آن عبارت ساجست
ندارد — یک نتیجه‌ی معتبر. بلاک شدن گوگل خودش را با HTTP غیر ۲۰۰ یا صفحه‌ی
کپچا (که JSON نیست) نشان می‌دهد. این دو شمارنده‌ی جدا دارند:
`max_consecutive_failures` (پیش‌فرض ۳) برای خطاها و `max_consecutive_empty`
(پیش‌فرض ۴۰) برای خالی‌ها.

Endpoint غیررسمی `suggestqueries.google.com`. قواعد ایمنی **در خود کلاینت**
اعمال شده‌اند تا قابل دور زدن نباشند:

- تأخیر تصادفی ۲ تا ۴ ثانیه بین درخواست‌ها (پاسخ‌های کش‌شده تأخیر ندارند)
- حداکثر ۳۰۰ کوئری در هر نشست
- هر نتیجه در `api_cache` — اجرای دوباره کوئری تکراری نمی‌زند
- سه خطای پشت‌سرهم → توقف با پیام، بدون از دست رفتن داده‌ی قبلی

پس از توقف، `--resume-from 3` فقط محصولات باقی‌مانده را می‌گیرد. اگر واقعاً
محصولاتتان ساجست ندارند، `suggest.max_consecutive_failures` را بالا ببرید.

نتایج در `lsi_keywords` (یک ردیف به‌ازای هر کلمه). اگر یک کلمه به دو محصول نسبت
داده شود، فقط برای محصولی می‌ماند که شباهت متنی بیشتری دارد. نتیجه‌ی خالی →
`no_suggest` و رفتن به شیت B (رکورد حذف نمی‌شود).

## تست

```bash
python -m pytest content_pipeline/tests -q
```

هیچ تستی به شبکه یا کلید API نیاز ندارد. پوشش: نرمال‌سازی روی ۲۰ نمونه‌ی
واقعی، سناریوی مرجع فاز ۲، idempotency و resume، کش و قواعد ایمنی ساجست، تداخل
LSI، حذف نام سایت، ساختار سه شیت خروجی، ویرایش‌های دستی (ادغام/جدا کردن/حذف
اجرا)، API پنل (توکن، فیلترها، اجرای پس‌زمینه، لغو و گزارش خطا)، و سالم ماندن
متن فارسی (صفحه‌ی `windows-1256`، BOM در config، خروجی هدایت‌شده).
